# Security

We take security seriously. Security issues in this repository or its automation should be reported privately.

This includes vulnerabilities in:

- source code
- CI and release workflows
- dependencies and update tooling
- secret handling and repository configuration

See [security standards](docs/developer/standards/security.md) for security, dependency, and automation posture in this project.

## Reporting

Do not open a public issue for suspected vulnerabilities.

Use GitHub private vulnerability reporting:

1. Open the repository Security tab.
2. Select Report a vulnerability.
3. Submit the details privately to the maintainers.

Include, where possible:

- affected file, workflow, dependency, or operational surface
- impact and likely attack preconditions
- reproduction steps or proof of concept
- suggested mitigation or patch direction

Reference: [Privately reporting a security vulnerability](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-a-vulnerability/privately-reporting-a-security-vulnerability)

## Maintainer handling

Maintainers will acknowledge the report, validate scope, coordinate remediation, and disclose publicly after a fix or mitigation is available.
