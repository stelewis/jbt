# Architecture

`jbt` implements local multi-account quantity builds and checked release replay for explicitly bound OFX bank/card evidence and authored facts. Pure resolution produces determinations and scoped findings; independent source and projected-table checks gate shared tables, a scoped Beancount projection, and a deterministic summary. Broader financial families have contract and conformance fixtures, not booking processors.

The [target architecture](../design/target-architecture.md) describes the intended pipeline. [Delivery](../plans/delivery.md) distinguishes contract proof, boundary feasibility, and later processor proof.

## Dependency direction

| Boundary | Owns | Dependencies |
| --- | --- | --- |
| `jbt.domain` | Bounded exact arithmetic, quantity vocabularies, explicit money states, civil time, stable identities, canonical encodings, typed rules and reviewed decisions, native compound guards, and journal custody | Python standard library; no IO, environment, plugin loader, or sink |
| `jbt.model` | Typed immutable source/quantity resolution, authority and revisions, original-position merge/enrich/link decision folds, complete rule evaluation, transfer booking, determinations, findings, proposals and pre-entry receipts | Domain only; no checks, runtime, adapters, or IO |
| `jbt.checks.quantity` | Independent per-extract source equations and projected model/occurrence/classification checks | Domain only; structurally prohibited from importing model |
| `jbt.contracts` | Versioned table catalog, closed JSON schemas, declaration and cross-record validation | Domain values and jsonschema; packaged schema data |
| `jbt.artifacts` | Catalog-aware physical rows and field provenance, explicit Parquet types, snapshot assembly and pinned reading, integrity, execution envelopes, logical content digests, scoped Beancount projection | Domain and contracts; no model or runtime imports; PyArrow at the file boundary |
| `jbt.extraction` | Strict importer protocol, caller context, version-1 source wire encoding and validation | Contracts and domain; no adapter imports, acquisition, classification, or booking |
| `jbt.importers` | Bounded OFX bytes to source observations and located unsupported-input failures | Extraction contract; selected through installed `jbt.importers` entry points |
| `jbt.storage` | Writer exclusion, immutable evidence, journal custody, complete attempt witnesses and report references, durable generation installation and current-reference replacement | Local filesystem operations and artifact integrity |
| `jbt.runtime` and CLI | Decode and adapt project evidence, project quantity determinations into financial rows, observe execution facts, execute the fixed graph, control cache and output policy, publish and verify uncached | Explicit model, storage, importer, domain, and artifact boundaries |
| Independent conformance consumer | Read pinned files, validate/replay published determinations, exercise consumer policy | DuckDB and independently implemented arithmetic; no `jbt` imports |

Import exact owning modules. Package initializers do not load native adapters or re-export their APIs. The consumer shares the published specification, not the producer's validator, serializer, arithmetic, or financial choices.

## Exactness and identity

Finite financial values retain a canonical coefficient, nonnegative scale, and separately stated source precision. Arithmetic admits bounded intermediates before calculation, retains rational values until an explicit rounding point, and reports unavailable components separately from known zero and inapplicable values. The [numeric contract](../design/analysis-boundary.md#exact-decimals-and-query-arithmetic) owns capacity and rounding semantics.

Economic identity uses domain-separated canonical anchors and stable child keys. `SourceKeyAnchor` carries typed namespace, section, key domain, and source key; its framing is `("source_key", scope, section, domain, key)`. It identifies an economic key family separately from the blob/context/locator of `AcquiredAnchor`. Source authority, changed values, display labels, and replay sequence do not choose identities. Explicit membership and reviewed merge/split transitions are inputs; the foundations do not discover duplicates or silently follow retired identities when applying corrections.

The shared tables represent nullable paired source keys on acquired occurrences, source-key canonical anchors, and explicit `event_support` membership under the [tabular contract](../design/analysis-boundary.md#evidence-declarations-and-relationships). Publication validation and the independent reader enforce occurrence/component uniqueness, retained evidence, and selected support for active non-retracted acquired events. Source-retracted events retain replaced support; retired identities have no canonical source membership or booked effects. Authored events use declarations without invented acquired support.

Compatible live observations of one scoped key/component resolve one event, with the smallest eligible source-record ID selected and the remaining support confirming. Authority selects financial facts, not identities; source-stated or reviewed revisions replace evidence only in their account/fact/basis/half-open scope. Disagreeing authoritative observations block rather than selecting an arrival winner. Key-family decisions persist across downloads; occurrence decisions separate reused keys; corrections never follow retired IDs. Keyless occurrences remain distinct without evidenced correspondence, and unresolved recognized overlap blocks. [Source overlap and revision](../adr/0014-source-overlap-authority-and-revision.md) owns these distinctions.

Generated identity framing and wire JSON serve different purposes. Declaration revision digests cover canonical typed JSON; row/guard and manifest encodings preserve typed meaning while rendering integer fields as canonical decimal strings. Schema JSON retains native integer constraints. Descriptive values retain exact Unicode and whitespace rather than being normalized; identifiers and object keys remain strictly validated NFC keys. The catalog declares each string/list column's `text_semantics`, and both producer and independent reader enforce it. Callers select the encoding explicitly; decoders do not accept alternate encodings as compatibility conveniences.

Synthetic conformance proves padded, decomposed, newline, and control-containing descriptive values survive publication and independent reading with unchanged financial answers. Distinct text bytes change row and guard digests without changing source-key economic anchors. The [OFX bank/card profile](ofx-profile.md) preserves descriptive source text exactly, strict identifiers, and bounded resources.

Decision guards address native source, statement, event or leg candidates, not fabricated final rows. Structural decisions seal every named operand's economics and current membership or scoped disposition. One domain evaluator returns closed `applied`, `missing`, `ambiguous`, `inactive`, and `changed` outcomes. Category, rule revision, descriptive overrides, lexical amount precision, and attempt identity do not become applicability proxies. The [decision-body contract](../design/decision-bodies.md) owns profiles and retained boundaries.

The pure `jbt.model.rules` fold evaluates every rule against typed pre-enrichment balancing-leg facts. Its contributions determine assignments, field provenance, diagnostics, and retained explanation; `show` does not recompute matches. The [bank/card rule contract](./rules.md) owns match fields, operators, and first/union policies.

Rules resolve before the pure `jbt.model.corrections.fold`. Active assignments and conserving boundary-leg splits execute in original first-record logical order, using each key's active revision. Each receipt owns all pre-entry candidates at its target address; one stage-tail inventory supports new decisions and inspection. Unrelated records are not repeated per decision. Supersession guards the original position, never its previous output. Two active assignments to one scalar field conflict; reproducing rule-only values is informational. All blocking outcomes prevent publication. Final-table validation does not reevaluate native guards against their own outputs.

Split children use the stable parent leg key, decision key, and authored child key. Physical revision, append sequence, source pointer, and changed amounts do not salt child IDs. Identical split supersession preserves dependent assignments; changed child amounts produce `changed`, not `missing`. Event and leg dates, descriptive assignments, and correction provenance live in the normalized model. A civil-date correction drops an inconsistent modeled time rather than inventing a new clock value; exact source-time evidence remains retained.

The [journal custody contract](../design/decision-journal.md) owns canonical headers, body seals, head selection, and structural history. Storage requires the root writer lock and expected head, synchronizes immutable objects before atomic head replacement, and refuses conflicting or additional orphans. Capture supplies every earlier applicable attempt head to detect valid-looking journal truncation and rollback. A live uncommitted suffix is reported and never financially applied. Merge decisions precede rules and enrich decisions; transfer and evidence-link decisions follow in the link stage. Participation remains source-derived, with reviewed cancellation only; pending-to-posted proposals never apply automatically. Interpreter qualification remains [deferred](./deferred-scope.md).

## Installed execution and retained financial inputs

Acquisition is outside the financial graph. Under one project-wide writer lock it preserves an immutable intent, copies and checks the original evidence, installs a content-addressed object, and commits its accession context. A retry key identifies the request, not an economic occurrence. Repeated accessions can share bytes without losing their distinct acquisition facts.

Users provision a published release with ordinary `uv tool install 'jbt==<release>'`. Standard installed distribution metadata identifies the production package name/version under the immutable, once-only [release policy](./standards/releases.md). The immutable release tag retains its source-commit provenance; release automation builds ordinary distributions, tests them, and publishes the same bytes without injecting a custom stamp. Index and archive installs trust their provisioning source, not runtime authentication. Directory and VCS source installs are development, including non-editable installs. No user Git checkout, cleanliness check, installation recipe, downstream lock, or wheel-hash proof is required. Python 3.14 or later is supported without a managed-runtime layout requirement.

The application observes producer identity, Python implementation/version, platform/architecture, and the names and reported versions of every installed distribution visible to metadata discovery. Names follow standard package-name normalization; records sort canonically, and missing metadata or duplicate normalized names fail. Discovery does not import discovered packages, load plugins, hash source or installed trees, invoke a package manager, or access the network.

Importer selection is a separate metadata-only preflight over `jbt.importers` entry points. Every selected name must resolve uniquely, with an identified owning distribution, before any selected adapter loads or execution selection is retained. Only selected plugins load. Each declares supported extraction contract version 1, a named profile with an importer-owned positive integer version, a positive byte cap, and `extract(bytes, ExtractionContext)`. A profile revision is provenance, not a new extraction contract version. Input caps apply before source inventory or object reads. Fresh and cached extraction documents both pass the closed version-1 schema and the caller's namespace/blob/importer binding. Execution provenance retains selected importer IDs, normalized owners, versions, profiles, contract versions and byte caps; extraction stage configuration binds those same facts. An omitted acquisition importer is archive-only evidence, never an executable source. The external importer interface remains experimental pending interpreter qualification; installed loading and strict replay do not approve a software-driven reinterpretation of retained history.

Extraction retains explicit stable account-context sections and their independent movement, settled-balance, available-balance, and pending-snapshot evidence parts. Records retain paired source keys, explicit source corrections, and raw status observations with profile-declared mappings. The OFX adapter supports multiple bank/card accounts and keyless pending evidence without deriving booking, original foreign amounts, revision order, or completeness. Domain `SourceTimeObservation` preserves full source calendar/clock evidence and exact second offsets separately from model `TimeObservation`; the [profile](ofx-profile.md#exact-values-and-time) owns source acceptance and unavailable interpretation cases.

Application processing denies supported Python socket and DNS operations before financial reads and heavy processing imports. Recorded attempts prevent publication authorization and successful verification even when a component catches the denial. This is not a native-code sandbox. External `uv` provisioning may fetch packages, Python, or advisory data before application startup; `jbt` itself never installs or repairs its environment.

The application holds writer exclusion from input capture through publication. Its retained selection names every expected accession, source object, authored project digest, observed execution record, explicit summary comparison pin, and selected journal head, canonical headers, bodies and bases. Missing retained financial inputs fail even with a warm cache. Financial roots contain no copied interpreter, dependency tree, source tree, or development lock. The captured project uses the shared declaration language and explicit source registries; the builtin field registry comes from the installed contract implementation rather than an author-supplied copy.

Each invocation has a distinct immutable attempt witness linking its ordinal to a content-addressed input selection. A complete explicit index and installation marker fail closed on lost metadata, unlisted witnesses, and edited selection seals; writers do not discover financial metadata by scanning arbitrary objects. The separately sealed `review_report_schema` report retains complete determinations, findings, existing rule observations, checks, and actual pre-entry evidence even when publication is blocked. Malformed or integrity failures have located errors and no invented financial determinations. Reports are queryable by attempt ID without opening the live project or journal. Decoding reuses a bounded process-local validation result only for identical report bytes and returns independent copies; storage still reads and verifies retained content and lineage on every access. Attempt identity is operational: retries over identical inputs can have different outcomes without replacing an earlier report or changing deterministic generation identity.

`show`, `review`, `correct`, `decide`, and `retract` require an explicit retained attempt. Writers construct guards from that report, check its head against live committed custody under the lock, and append without rerunning resolution. The [quickstart](../user/quickstart.md#review-and-correct-a-record) owns command examples and supported assignment fields.

## Quantity resolution and independent checks

The fixed sequential graph is extraction → source checks → model → model checks → enabled outputs → assembly. Quantity processing binds and merges evidence, applies rule and decision folds, and derives booked effects; source and projected-model checks are separate runtime stages, never calls from the pure resolver. `resolve(Inputs) -> Resolution` takes immutable semantic values and returns complete determinations plus scoped findings; blocked is a resolution status, never an economic event state. Malformed inputs, corrupt evidence and arithmetic capacity violations fail rather than producing invented determinations. Identity, guard and arithmetic failures cannot be waived. `jbt.model.quantity` owns the shared event-date and leg-inheritance interpretation used by correction folding and publication.

Each extracted section must bind exactly once to an effective account declaration or be explicitly ignored with a reason. Account-number changes can use dated bindings to the same account. Scoped, dated commodity symbols must resolve uniquely; conflicting global and scoped mappings fail. Positions resolve by account, commodity and optional source position key, never by netting ambiguous same-commodity positions.

A card uses the same quantity model as a bank account: its position is a claim against the issuer, owing is negative, and an overpaid positive balance keeps the same position and liability rendering. A card payment is an internal transfer, not a separate event or link kind.

Transfer decisions own named source position legs. Booking derives their balancing legs in the declared in-transit position rather than classifying an internal payment as income or expense; the independent checks enforce exact conservation for complete transfers. Document and lifecycle links do not change quantities or participation. The [decision-body contract](../design/decision-bodies.md) owns operands, membership and stage-specific guards; the [user workflow](../user/quickstart.md#decide-transfers-and-attach-evidence) covers one-sided and month-end transit.

`jbt.runtime.resolution` owns project-specific wire decoding, declaration/source adaptation, and the canonical mapping of quantity determinations to financial catalog grains. Preparation decodes each declaration once and indexes retained source observations before adapting movements. It keeps only supplemental transaction/posting fields for publication, not raw payloads to reinterpret after resolution. Determinations own identities, support, dates, amounts, classifications, and corrections; retained supplemental fields cannot overwrite them. `jbt.artifacts.projection.Rows` owns physical decimal expansion, field provenance, and catalog ordering without knowing model types or choosing financial meaning. Source checks intentionally decode retained extracts independently; model checks decode projected tables into typed evidence and do not inspect model internals. No model operation calls checks.

Output policies select actual check kinds. Missing or unavailable required evidence is not success, and running a stage does not certify a check. Working unclassified records are permitted unless the output requires classification. Effective nonoverlapping declaration revisions are retained and selected by applicable date: bindings, symbols, rules, and assertion scopes use their observation/event date; authored facts use the model horizon. Account opened/closed dates, not policy revisions, own position lifetimes.

Release stage identity includes all observed execution facts, schema, relevant effective declarations, full retained source/status semantics, horizon, each check policy, and named ordered input edges. Even an unrelated visible distribution changes cache identity. Validate cache envelope claims and bounded payload bytes before reuse, report byte corruption before recomputing, and reject unsafe paths or schema-invalid extraction rather than silently accepting them. A directory or VCS install of either `jbt` or any selected importer makes the entire execution development before cache activity: no persistent cache reads, writes, or directory creation, and no mutable-source hashing. Financial checks are not configuration-supplied success flags.

Account civil dates resolve with retained timezone rules, not the ambient system zone. The [civil time, coverage and lifecycle contract](./coverage.md) owns temporal conversion, due periods, card cycles, exact gaps and account lifetimes. Locale-independent financial parsing/formatting and canonical ordering keep locale and hash iteration out of financial meaning and cache identity. An installation must stay quiescent during a command; developers must likewise avoid concurrent source edits. Same-version installed-file tampering is outside this trusted-provisioning contract.

Source equations pair compatible source points within one namespace/section and one extract's covered movement span; authored initialization citations do not assign source opening roles. Only that interval's explicit row membership between the actual points participates, never a union of downloads or points borrowed through a shared modeled account. Without a single covering extract the equation is `not_evaluable`. Independent model equations read projected tables, detect omitted debits and distinguish net from positive/negative gross assertions. A net assertion does not certify gross positions; a partial set does not assert omitted positions are zero.

Pending, cancelled and retracted events remain inspectable without booking. Summary quantities include recognized effects regardless of review label; review counts are grouped by event state. Uncategorized work counts recognized null-category boundary legs and reports amounts per commodity, with account attribution only when one account owns all the event's position legs. Multi-account work is explicitly unattributed; pending and blocked counts are separate. Beancount renders recognized events only, with `!` for unreviewed and `*` otherwise. It rejects unclassified boundary legs with `unclassified_boundary`; working tabular and summary outputs retain that backlog. OFX search bounds do not establish complete source coverage. The [source profile](./ofx-profile.md) owns retained evidence and format limitations.

## Artifact assembly and publication

`assemble_snapshot` receives the complete non-build table set, explicit entity and execution facts, retained interpretation resources, opaque output payloads, and writer settings. Assembly and pinned reading enforce the same contract: schema-typed JSON is canonical, retained artifact logical digests are checked, and published stage envelopes resolve to actual payloads with matching schema and digests and unique input ordinals. Payload roles come from the manifest, not filename extensions. Assembly validates the complete candidate and writes into a caller-owned empty directory:

1. Serialize the schema resources and write non-build Parquet tables, including typed empty tables.
2. Record byte and logical table digests, retained inputs, configuration, checks, and execution settings in the manifest.
3. Hash the manifest and write `build.parquet` with that digest.
4. Write the descriptor last, covering all payload bytes without a checksum cycle.

Storage validates and synchronizes the complete candidate, installs its immutable generation without replacing an existing one, and atomically replaces a small current reference. It acknowledges durability only after synchronizing that reference's directory. Readers pin a descriptor once and never mix files from different generations.

A failure before current-reference replacement leaves the old generation selected. A failure after replacement but before durability acknowledgement is explicitly uncertain acknowledgement; the selected generation is still complete. Fault injection establishes these application boundaries, not arbitrary hardware power-loss guarantees. Source objects, prior generations, and failed-attempt input selections are not garbage-collected.

Financial-content identity includes semantic schemas, effective declarations, interpretation registries, bindings, retained derivation semantics, findings, and typed financial rows. Rendering settings, physical encoding, recovery locations, and summary comparison context are execution concerns. Byte integrity is not semantic validity: the independent conformance reader also exercises altered rows with recomputed mechanical checksums.

`verify --root <root> --baseline <descriptor-digest>` requires the baseline's published `jbt` and selected importer versions, owning distributions and declared profiles/contracts, not development code with matching version labels. It validates the historical recovery selection, physical integrity, schemas, and exact inventory, then rebuilds in isolation with no persistent cache reads or writes. Source-commit provenance and supported Python/platform/other-distribution differences are descriptive, not replay compatibility gates. Interpreter qualification is deferred; there is no approval gate or qualification command.

Replay compares typed financial tables, precision, lineage, effective declarations, derivation definitions, findings, exact model review evidence and receipts, financial-content identity, and deterministic ledger/summary output. It replays only the captured journal headers, bodies, head and bases, never later live entries, suffixes, or metadata. Build rows, observed runtime facts, execution fingerprints, recovery locations, physical Parquet bytes, and mechanically dependent manifest/descriptor IDs are operational differences, not financial mismatches. Located contract, domain, importer, and sink failures include the recorded and observed environments in replay diagnostics; build failures also identify their retained attempt. Replay does not compare whole manifests or change the baseline/current reference. Success proves replay in the observed supported environment, not every future installation.

`build --root <root> --project project.json` takes an optional `--comparison-baseline <descriptor-digest>`. An absent pin means no comparison, not whichever generation is current. An explicit summary baseline is comparison data only; its earlier comparison chain is not recursively replayed.

## Sinks and consumers

Parquet preserves the shared model directly, not a ledger-shaped intermediate. Beancount is a scoped projection of already determined weights and inventory slices. It cannot pick lots, invent basis, infer missing dates, or insert a rounding plug. Unsupported representations raise named sink limitations while leaving the upstream record unchanged.

The ledger conformance tests cover explicit signed lots, finite-cost action removals/readditions, transfers, disposal gains, mixed consideration, notes, declaration lifetimes, and supported unit assertions. Reference/pool inventory and transactions with differing posting dates remain outside this projection; it does not manufacture inventory costs or clearing legs. Real-loader probes distinguish negative market-price directives, which are supported, from negative posting-price annotations, which Beancount rejects. An unvalued exchange cannot be made balanced by inventing a price.

The real Beancount loader demonstrates a consequential limit: total cost 10 over three units becomes a finite rounded unit cost. The exact source total and partial allocations therefore cannot be certified by accepting Beancount's inferred tolerance. This case remains exact in the tabular contract and explicitly unsupported by the scoped ledger projection.

The independent reader folds recorded steps atomically and reconstructs inventory, component lineage, quantity positions, references, and scoped assertions. It does not apply action ratios again or calculate another settlement. Consumer-specific valuation, ownership, flow perimeter, or matching choices are explicit inputs to separate conformance examples, not new upstream determinations.

## Contract conformance

The shared corpus includes a nonempty specimen for every table and complete cases for independent financial replay. Representative cases cross the real Parquet, DuckDB, and Beancount boundaries. Recorded inventory, action, and analytical examples establish representation and consumer behavior; their producers remain [deferred](./deferred-scope.md).

Installed acceptance covers packaged resources, entry points, release provenance, cache reuse, and relocated replay without live inputs, project, or cache. See [testing standards](./standards/tests.md) for proof selection and [local workflows](./tools/local-workflows.md#contract-conformance) for commands.
